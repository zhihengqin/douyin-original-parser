# 2026-11-16：完整响应审计、原画校验修复与下载验收

本轮已修改生产代码，并实际恢复一个此前会被媒体校验误拒的官方原画：`7698054262056552561`。完整文件为 **40,087,514 字节、1080×1920、46.249 秒、HEVC/AAC**，下载 MD5 与本轮官方 `original` 回包一致。

用户重点关注的 `7708052871413075238`、`7707993970332290314`、`7707964786692083007`，以及当前 `parse_links.py` 的 `7706218040236444937`，本轮仍未首次取得原片。此次修复不表示这四条已经恢复，更不表示所有抖音作品都能保证取到上传原文件。

## 生产算法的实际变化

1. **利用已下发的内嵌视频模型。** `video_model.video_list[*].video_meta` 和平铺 fplay 档位现在共用严格的原画选择器。详情中已有有效 `original/source` 时直接校验，减少额外请求；不会因为没有 `fallback_api` 就丢弃内嵌原画。
2. **逐路完成媒体校验。** 原先第一路有原画候选就停止取址，即使这些地址全部失效也不再尝试下一路。现在按内嵌模型、original 选择、source 选择继续检查；同一完整 URL 不重复 probe，成功即停止。限流不触发额外路线。
3. **用当前回包的原画身份重新分发。** 当前官方回包明确标记 `original/source`，且提供完整 FID、MD5、大小、分辨率及时间信息时，即使地址缺失、无法解码或失效，也能使用这份即时身份请求官方重新分发。该路线不需要调用者提供 MD5，也不需要历史 catalog；原画格式、加密、作品身份校验仍生效，重新取得地址后仍须媒体校验。
4. **补齐官方备用 CDN。** 新增 `zjcdn.com` 的严格域名匹配。两条目标实际下发的该域地址均已验证为 HTTP 206、MP4 头和正确总长。
5. **完整收集已知转码。** 默认档排除检查加入内嵌 `video_meta` 和两路 fplay 的所有转码大小，修复仅看 `play_addr/bit_rate` 少算档位的问题。此为拒绝已知转码的补强；“与已知转码不同大小”本身仍不是上传原文件的充分证明。
6. **修复 QuickTime 轨道误识别。** 只有直接位于 `mdia` 下的 `hdlr` 定义视频／音频类型；`minf/hdlr` 的数据处理器 `url ` 不再覆盖 `vide/soun`。真实官方原画因此恢复。
7. **修复默认档下载。** 旧默认档候选始终缺少 `file_hash`，完整下载后必然被当作 MD5 不匹配。现在优先采用官方元数据或 CDN `Content-MD5`；存在官方哈希时严格比较。上游没有提供哈希时，完成字节数、完整音视频、时长、分辨率检查并计算本地 MD5/SHA-256，返回 `official_hash_match: null`，不把本地计算冒充官方校验。

原有登录对照工具同步适配内嵌模型和新的候选选择器，防止把一次本地复验重复统计成额外的官方目录。

合计 **295 次 HTTP、204 条地址、17 个不同 MP4**。17 个媒体对象全部通过实际音视频与作品时长校验，但没有任何 `original/source` 档位，也没有取得先前参考原片的 140,778,272 / 38,562,411 字节对象。8 条 404 地址均来自 `download_addr`。完整报告分别在 `output/research-astar/official-audit-<作品ID>.json`；报告不含完整签名 URL、Cookie 或令牌。

递归检查两目标网页/App 回包共 **5,681 个节点**，包括 JSON 字符串中的 `video_model`、`video_extra` 和 `meta`。网页详情有播放 token，App 详情没有，不能把 App 的现象泛化成所有接口。新公开线索所涉及的 `encode_user_tag`、`force_fids`、codec 和 `vquality` 做了 **6 配置 × 2 目标** 对照，未新增原片身份。

“所有内容”在这里指上述实际返回的视频字段、档位和不同主备地址；没有声称遍历了未公开的全部抖音接口。审计报告会记录接口失败、请求预算耗尽和遗漏候选，避免将不完整测试写成完整结论。
