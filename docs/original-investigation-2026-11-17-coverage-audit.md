# 2026-11-17：接口覆盖与跨来源组合复核

没有证据支持“所有接口，包括隐藏接口的全部内容都组合使用过”。已完成的是一组已知 Web/App/SDK 入口、已取得回包的字段合并，以及部分文件身份之间的链式请求。没有有效响应基线的分支不能算已排除；静态发现接口名称也不等于完整重放了实际业务流程。

旧取址流程无法覆盖部分仍可由官方分发取得的文件，说明当前发现链不足；它不能单独定位变化发生于客户端选档算法、服务端资源下发策略、登录/设备上下文、第三方历史缓存中的哪一环。

## 本轮确认并修正的组合缺口

`tools/audit_official_sources.py` 之前会把最小 Web、PC、App 返回的视频候选交给同一收集器，但后续 fplay 只使用最先选中的详情模型。存在“某次 PC/App 回包另有模型，却没有沿其 fallback_api 继续查询”的覆盖缺口。不能因普通媒体候选已合并就声称取址链全部合并。

本轮改为逐一处理每个成功且身份匹配的详情中的主 `video_model`：

- 每份模型各自执行 issued/original/source 三条已有路线，issued 使用原样签发地址。
- 保留该模型 VID、完整 fallback、对应响应的 key_seed；App 路线继续使用 App User-Agent，不将 Web/App 签名字段拼成一个新请求。
- 只有 VID、完整 fallback、请求头都相同才去重；报告保留所有来源。
- 新增 `model_contexts`、`fplay_context_count` 和路线 `context_origins`，明确模型缺失、请求成功、失败及未完成状态。
- 遇到请求预算或 429/444 停止后续请求，保留已取得候选。

这是审计工具的覆盖改进，不是已经发现新原片的生产修复。工具内现有通用 App 分支仍是旧版参数；此前 41.1.0 官方 signer 的专项请求由单独研究脚本执行，本轮没有将其登录业务完整整合。

已更新现有 `tests/test_source_audit.py`，验证只有第二模型才有候选、相同 VID 的不同签发上下文、App User-Agent 保留、Web/PC 相同上下文去重及来源合并、后续上下文达到预算或 429 后仍保留先前候选。专项结果为 **18 passed、14 subtests passed**；没有新增测试文件。

## 本轮实时对照

用独立匿名访客执行最小 Web、PC 和各自可用主模型的 fplay；关闭旧版 App 分支、原片 catalog 和外部资产恢复，没有把小帅对象身份作为发现请求输入。两条作品各 5 次请求，合计 10 次官方 HTTP 尝试；浏览器匿名访客初始化资源另计。没有媒体下载和付费解析。

| 作品 | 主模型来源 | PC 主模型 | 已完成 fplay 上下文 | 显式 original 候选 | 请求错误 |
| --- | --- | --- | ---: | ---: | --- |
| 7695305664234589459 | 最小 Web | 空 | 1 份模型 × 3 路 | 1 | 无 |
| 7708319942491344154 | 最小 Web | 空 | 1 份模型 × 3 路 | 0 | 无 |

本轮 PC 没有额外模型，所以多上下文改进没有在这两条实测中增加 fplay 请求。目标仍有 12 个候选地址身份组和 1 个独立音轨候选，未出现新取得的 266 MB 对象的 MD5。阳性显式 original 未在本次再次做媒体验证，故工具 `original_verified=false` 不代表阳性失效。

脱敏实时报告位于 `output/combined-context-audit-20261117/770831.json`、`positive.json`。`incomplete=false` 只表示本轮启用的已知路线没有请求错误，不能解释为全平台接口已覆盖。

## 用新文件身份反查现存档案

以 770805 的 140,778,272 字节参考文件、770831 的 266,189,150 字节新对象的 MD5、对象键和大小，反查当前 `output/` 与 Temp 中 9 个相关研究目录。共发现 2245 个 JSON/TXT 文件，读取 2244 个，解析 1726 份 JSON，展开 11368 个嵌套 JSON、1036 个播放器地址和 1058 个 UTF-8 Base64 文本。这些数量包括研究摘要、代码索引及资料，不是接口数量或纯官方回包数量。

未在当前留存的此前官方原始回包里命中这两个目标身份；有效命中集中于本次小帅、媒体检查和已知资产重签资料。旧 `play-url-list` 文本中对象键的命中实际是“详情内出现该对象键：0次”，不算发现。

范围限制：一个超过 8 MB 的 SDK 文件树未读；两个代码消费者/SDK 文件树达到递归节点预算；它们不是视频回包。未扫描 APK、任意二进制或 Java 大树。

更重要的是，下列旧原始目录当前不存在：`output/login-retry-20261117`、`output/research-astar-user-hints/demo`、`output/research-astar-continuation-20261117`、`output/research-astar-round2`。本轮不能重新复核其中每份历史回包，只能引用已持久化报告的限定结论。不能据本次反查将历史所有原始档案宣称为重新全量审计完成。

当前明确缺口仍是有效 App 会话、batch/IM 的有效请求基线、真实客户端成功取址时的动态业务链，以及小帅服务端的上游发现过程。没有证据支持把这些缺口当成已测试无效。
